# Roadmap

## 已完成

- 使用真实 Bangumi token 在真实 Obsidian 库中测试完整同步流程。
- 改进 token 过期、权限不足、Bangumi API 限流等错误提示。
- 增加 token 获取页面、剪贴板填入和手动 `Test token` 辅助。
- 支持书籍、动画、音乐、游戏和三次元条目类型。
- 支持文件命名、存储逻辑和是否同步搁置/抛弃条目的设置。
- 基于 Bangumi `updated_at` 实现增量同步，并在本地文件缺失时补回。
- 增加 Daily Notes 同步块。
- 增加用户可编辑的 Markdown 条目笔记模板。
- 通过模板支持自定义 frontmatter 字段。
- 生成同步失败报告。
- 增加每日放送笔记，按星期展示全站放送和想看/进行中的动画收藏。
- 增加轻量测试，覆盖 Markdown 渲染、同步块合并、重复文件防护和误删文件补回。
- 增加发布打包说明、版本号更新脚本和社区插件发布 checklist。
- 扩展可选导入内容：基本信息（标题、类型、话数等）、制作人员（Staff）、角色信息（Characters）、关联条目（Relations）、用户收藏状态和评分。
- Bangumi 风格看板/格子 UI：作为未来替代直接编辑 Markdown checklist 的更安全交互。
- 状态、评分、评论写回前显示更明确的 diff 预览。
- [X] 双向同步：为想编辑部分生成内容的用户提供更安全的合并策略。
- [x] 完善未收藏条目的写回流程。
  - [x] 单独同步远端未收藏条目时，创建本地笔记并自动Push 创建 Bangumi 收藏。
  - [x] Push 前如果远端收藏不存在，应显示“将新增收藏”的预览，而不是直接失败。
- [x] 区分“已看章节数量”和“连续看到第几集”的进度语义。

### 已有问题

- [x] 从 Bangumi 单独拉取但未收藏的条目，本地修改状态或章节进度后 Push 可能失败；当前流程不会自动加入收藏。
- [X] 多集进度同时写回，远端显示可能只显示“最后一个章节已看”。
- [X] 部分索引和看板操作会枚举全库 Markdown 文件再按同步目录过滤，需改为目录内遍历或缓存索引。
- [x] 日记进度同步成功，显示同步错误(多余操作导致)
- [x] 看板与 Markdown 文件一同更新：章节 Push 后更新 checklist 和 `progress_done`；状态、评论、评分写回后重新渲染条目笔记。
- [x] 本篇与其他类型章节混合在一起的问题。
- [x] 章节较多条目拉取进度存在上限。

## 后续增强

- [ ] 优化同步目录索引方式，减少全库 Markdown 枚举带来的隐私疑虑和性能成本。
  - [x] 优先从 `syncDirectory` 对应目录递归遍历，而不是先调用 `app.vault.getMarkdownFiles()` 再过滤。
  - [ ] 为条目索引和看板列表增加缓存，并在文件创建、删除、重命名或同步目录变化时失效。
  - [ ] 在文档中明确说明插件会读取/索引哪些范围的文件。
- [ ] 细化写回安全设置。

  - [ ] 避免在用户未明确选择时把评分写回为 0 或清空远端评论。
- [ ] 提升大库同步性能。
  - [ ] 根据收藏状态和条目类型选择性拉取章节进度，例如 `game`、`music` 默认不拉章节。
  - [ ] 对 429 限流进行自适应降并发，而不仅是单请求重试。
  - [ ] 在一次同步内缓存 `getMe()`、章节列表和额外条目信息，减少重复请求。
- [ ] tag设置：为文档tag添加更多自动验证内容。
- [ ] 可选按状态、年份、标签或条目类型创建索引笔记。
- [ ] Oauth登录。
  - [ ] 如果之后有不需要用户管理 client secret 的公共客户端流程，再重新评估 OAuth 登录。
- [ ] 提供更友好的自定义 frontmatter 字段 UI。
  - [ ] 根据真实用户反馈继续调整默认模板和 Daily Note 同步格式。
