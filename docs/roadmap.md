# Roadmap

## 已完成

- 使用真实 Bangumi token 在真实 Obsidian 库中测试完整同步流程。
- 改进 token 过期、权限不足、Bangumi API 限流等错误提示。
- 增加 token 获取页面、剪贴板填入和手动 `Test token` 辅助。
- 支持书籍、动画、音乐、游戏和三次元条目类型。
- 支持文件命名、存储逻辑和是否同步搁置/抛弃条目的设置。
- 基于 Bangumi `updated_at` 实现增量同步，并在本地文件缺失时补回。
- 增加 Daily Notes 同步块。
- 增加用户可编辑的 Markdown 条目笔记模板。
- 通过模板支持自定义 frontmatter 字段。
- 生成同步失败报告。
- 增加每日放送笔记，按星期展示全站放送和想看/进行中的动画收藏。
- 增加轻量测试，覆盖 Markdown 渲染、同步块合并、重复文件防护和误删文件补回。
- 增加发布打包说明、版本号更新脚本和社区插件发布 checklist。
- 记录移动端兼容性可能不佳，并建议移动端谨慎使用。

## 后续增强

- [ ] 提供更友好的自定义 frontmatter 字段 UI。
  - [ ] 根据真实用户反馈继续调整默认模板和 Daily Note 同步格式。
- [X] 双向同步：为想编辑部分生成内容的用户提供更安全的合并策略。
- [ ] 完善未收藏条目的写回流程。
  - [ ] 单独同步远端未收藏条目时，允许用户只创建本地笔记，或显式确认后 Push 创建 Bangumi 收藏。
  - [ ] Push 前如果远端收藏不存在，应显示“将新增收藏”的预览，而不是直接失败。
  - [ ] 新增收藏成功后再写回章节进度，并分别报告“收藏创建”和“章节写回”的结果。
- [ ] 区分“已看章节数量”和“连续看到第几集”的进度语义。
  - [ ] `progress_done` 继续表示已勾选章节总数。
  - [ ] 增加连续观看光标字段，例如 `progress_cursor` / `last_contiguous_episode`。
  - [ ] 避免把零散勾选中的最后一集误显示为“看到最后一集”。
  - [ ] SP、OP、ED、番外等特殊章节默认不参与连续进度计算，或提供可配置策略。
- [ ] 优化同步目录索引方式，减少全库 Markdown 枚举带来的隐私疑虑和性能成本。
  - [ ] 优先从 `syncDirectory` 对应目录递归遍历，而不是先调用 `app.vault.getMarkdownFiles()` 再过滤。

  - [ ] 在文档中明确说明插件会读取/索引哪些范围的文件。
- [ ] 细化写回安全设置。
  - [ ] 将总开关拆分为章节进度写回、收藏状态写回、评分写回、评论写回和看板写回。
  - [ ] 状态、评分、评论写回前显示更明确的 diff 预览。
  - [ ] 避免在用户未明确选择时把评分写回为 0 或清空远端评论。
- [ ] 提升大库同步性能。
  - [ ] 根据收藏状态和条目类型选择性拉取章节进度，例如 `game`、`music` 默认不拉章节。
  - [ ] 对 429 限流进行自适应降并发，而不仅是单请求重试。
  - [ ] 在一次同步内缓存 `getMe()`、章节列表和额外条目信息，减少重复请求。
- [ ] tag设置：为文档tag添加更多自动验证内容
- [X] 扩展可选导入内容：基本信息（标题、类型、话数等）、制作人员（Staff）、角色信息（Characters）、关联条目（Relations）、用户收藏状态和评分。

## 已有问题
- [ ] 集数重复、包含多个相同集，此类问题暂未解决（ex：假面骑士ZZZ）
- [ ] 从 Bangumi 单独拉取但未收藏的条目，本地修改状态或章节进度后 Push 可能失败；当前流程不会自动加入收藏。
- [ ] 多集进度写回后，远端显示可能把误当成“最后一个已看章节”。
- [ ] 部分索引和看板操作会枚举全库 Markdown 文件再按同步目录过滤，需改为目录内遍历或缓存索引。
- [ ] 进度同步成功，显示同步错误(多余操作导致)
  ```markdown
  ### 1. 写入每日日记同步块
  - 阶段: 写入每日日记同步块
  - 错误: 没有找到每日日记同步块标记。请先把同步块放进你的每日日记模板。
  ```
